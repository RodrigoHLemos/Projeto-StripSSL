Controles Criptográficos e Mitigação

Este painel permite alternar a configuração de segurança do servidor web para fins de demonstração acadêmica, conforme fundamentado na revisão de literatura sobre OWASP A04:2025, Marlinspike (2009), RFC 6797 (HSTS) e a norma ABNT NBR ISO/IEC 27002.

Modo Atual: {% if modo == 'mitigado' %} MITIGADO (Ambiente Seguro) {% else %} VULNERÁVEL A SSL STRIPPING {% endif %}
{% if modo == 'mitigado' %} O cabeçalho Strict-Transport-Security é enviado em todas as respostas e os cookies de sessão possuem as diretivas Secure; HttpOnly; SameSite=Strict. {% else %} O servidor permite conexões HTTP desprotegidas, não envia o cabeçalho HSTS e emite cookies sem a diretiva Secure. {% endif %}
Cenário 1: Vulnerável (Antes da Mitigação)
  • HSTS: Desativado (ausente dos cabeçalhos).
  • Redirecionamento: HTTP 302 para HTTPS facilmente reescrito pelo Bettercap.
  • Cookies: session_id=...; Path=/ (sem flag Secure).
  • Resultado: Atacante executa ARP Spoofing + SSL Strip, rebaixa para HTTP texto claro e sequestra a sessão da vítima.
HTTP/1.1 200 OK
Set-Cookie: session_id=sess_...; Path=/
# Strict-Transport-Security: AUSENTE
Cenário 2: Mitigado (HSTS & ISO 27002)
  • HSTS (RFC 6797): Ativo com max-age=31536000.
  • Navegador: Converte internamente qualquer requisição HTTP para HTTPS antes de tocar a rede (Internal 307 Redirect).
  • Cookies: session_id=...; Secure; HttpOnly; SameSite=Strict.
  • Resultado: O ataque de SSL Stripping falha categoricamente. O Bettercap não consegue rebaixar a conexão.
HTTP/1.1 200 OK
Set-Cookie: session_id=...; Secure; HttpOnly; SameSite=Strict
Strict-Transport-Security: max-age=31536000; includeSubDomains
